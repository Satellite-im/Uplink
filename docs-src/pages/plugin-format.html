A plugin is one file of JSON, named <id>.ghostplugin, in the ghost-plugin/1 format: one object holding the fields below. It's at most 256 KB (262,144 bytes) and nested at most 8 deep. Numbers in it are whole numbers, and null appears only where a field says it may. A key the format doesn't have is a problem at any depth (unknown_field), so a reviewer sees everything a plugin holds. Developer mode loads any file name, and the file laid out however you like.

Web and email addresses

A web address (in links, a link button's url, or support) is https, at most 200 characters, with no user name or password, no port, no # part, no spaces and no { or }. A query is allowed, but it's fixed: nothing from a text is ever put into an address. Its host is two or more parts of lower-case letters, digits and inner hyphens (example.com), none starting xn--; never an IP address, never a name ending .local, .lan, .home, .internal, .localhost or .arpa, and never gogho.st or ghost-sms.com, whose addresses the app opens itself (bad_url otherwise). An email address, for support only, is the usual name@example.com, its domain held to the same rules (bad_email).

Icon names

For symbol, and a section's, an action's or a setting's icon: any of the app's own icon names below. ghost, store and shield-check are kept for the app itself (its mark, the Marketplace and "Can't reach the internet"), and any other name is bad_icon_name.

The examples' ids, bills and parcels, load in Developer mode like any other, but can't be submitted (id_example: "That's the example's id: give your plugin an id of its own."), so nobody takes the id every reader of these pages starts with.

The icon

  • Not needed in Developer mode: without one, the plugin's tile draws its symbol on its hue. Submitting needs one, and the submission form makes it for you from any picture you choose or paste (256 pixels a side, smaller if it must be), so you only need what follows to put one in the file yourself.
  • A PNG, square, 64 to 512 pixels a side, holding only the chunks IHDR, PLTE, tRNS, sRGB, gAMA, pHYs, IDAT and IEND, with nothing after IEND: so no animation, no text, no EXIF and no colour profile (bad_icon otherwise).
  • In base64, the standard alphabet with = padding and no spaces or line breaks: at most 48,000 characters, and at most 36,000 bytes once decoded.
  • It's drawn over the plugin's hue, filling its tile. Transparent parts show the hue, so a white glyph on transparency looks like a built-in plugin's tile.

To make the base64 on a Mac:

base64 -i icon.png | tr -d '\n'

In PowerShell on Windows:

[Convert]::ToBase64String([IO.File]::ReadAllBytes('icon.png'))

Words in a plugin

Every string in a plugin, its phrases included, keeps these rules (bad_text, or phrase_bad_text for a phrase):

  • No space at its start or end.
  • One line. Only the description, whatsNew and settings' hints may have line breaks, and only the plain one (\n).
  • Nothing invisible: no control characters, zero-width spaces or joiners, direction marks or overrides, soft hyphens, private-use characters (one draws a company's logo on some systems), tag characters, or blank-looking letters that make a name look empty.
  • Lengths are counted as JavaScript and Dart count them, in UTF-16 code units: most letters are one, and an emoji is often two.

A name, and a section's label, can't be a built-in plugin's or one of their tabs' and kinds', nor have uplink, ghost or gogho in it (name_reserved). They're compared with look-alikes folded first, so "Сodes" with a Cyrillic С, or "Ｃｏｄｅｓ" in wide letters, is still Codes.

Settings

Each setting is an object with a type, shown on the plugin's page in the order written; a heading starts a new card.

typeFieldsShown as
togglekey, label (1 to 60), hint (1 to 200), icon, and default (true or false, required)A switch
choicekey, label, hint, icon, options (2 to 8 of {"value", "label" (1 to 40), "hint" (1 to 120)}), and default (one of the values: choice_default otherwise)A choice of one
wordskey, label, hint, icon, placeholder (1 to 60)A field for the person's own words, a line each or with commas between: what a rule does with them
notelabel, hint, iconA line of words
headinglabel, hintA heading over the next card
  • hint, icon and placeholder may be left out; everything else in the table is required.
  • Keys are unique across a plugin's settings (duplicate). A rule that names a setting must name one there, of the right kind (unknown_setting).
  • A toggle an incoming rule names must start off ("default": false), and is switched off again when the plugin is removed. On a computer or an iPhone its hint says it does nothing there.
  • The person's choices are kept when they remove the plugin, and are there again if they add it back.

The form it's sent in

When you submit a plugin, the app sends it in one fixed form: every object's keys sorted, no spaces or line breaks, every string written the one way. The Marketplace takes only that form, so a plugin's SHA-256 names exactly one file, and a change of one character is a new file that needs a new review. You never have to make it yourself: the submission form does, from whatever you loaded. Developer mode takes the file just as you wrote it.
