Try it in Developer mode

Load your plugin from a file, a link or the clipboard, try it on a text, reload it, and read what went wrong.

Developer mode loads a plugin you're making straight onto your own device, unreviewed, so you can try it, change it and load it again before anyone else sees it. Everything here is in Settings › Developer › Plugins in development, and on each plugin's own page there.

Developer mode

Turn it on with twelve taps on Settings › About › Version (how). Plugins in development load only in Developer mode, and run only while it's on: switch it off and they stop, switch it back on and they're there again. While one is on, the list of conversations says so in a quiet line: A plugin in development is on · Settings › Developer. They show in the Marketplace too, under Marketplace › In development and as In development · not reviewed on their pages, so one never looks like a reviewed plugin.

Tap a plugin's row in Settings › Developer for its page there: where this copy came from and when, its Problems, what it ran into Lately, Try it, its own settings once it's on, and Reload, Open in the Marketplace, Submit it to the Marketplace and Remove. Its page in the Marketplace leads back here, so changing it, reloading, trying it and reading what went wrong all happen in one place.

Load a plugin from a linkYesYesYesYes
  • A link is https to anywhere, or plain http only to the device itself: http://127.0.0.1 on Android, which reaches your computer through adb reverse, and 127.0.0.1, localhost or [::1] on a computer. Anything else says "Use http://127.0.0.1 with adb reverse, or https."
  • A link may redirect three times, each to an address the same rule allows. It has 10 seconds to answer and 20 in all, and the file is at most 256 KB.
  • Each load says how it went: "Bills loaded", "Bills loaded. Switch it on to agree to what it can do now.", or what was wrong.
  • Loading a copy with the same id as one loaded already takes its place, switched on or off as that was.
  • An id a plugin from the Marketplace has on this device is refused: "Bills is installed from the Marketplace. Remove it there first, or give your copy another id."
python3 -m http.server 8080      # on your computer, in your plugin's folder
adb reverse tcp:8080 tcp:8080    # then load http://127.0.0.1:8080/yours.ghostplugin on the phone

Try it, and the samples

A plugin's page in Settings › Developer has Try it, which runs it on words you type as if they'd come from a number not in your contacts. Nothing is sent, no text has to come, and it works on every platform, an iPhone's too.

  • Type the text, and who it's from if it matters (72975 if you leave it). Every switch on tries it with all of its switches on.
  • Try it says the tags it gave and what each kept, the tab or kind it goes to, its row's value and caption, the buttons it offers in each place, what it would do as the text came (mark read, silence), and how long it took.
  • Where a built-in plugin that's on would take the text first, it says which: "In this app, Kinds of text › Payment reminders takes this text first". That's built-in plugins sorting first; switch that kind off to let yours have it.
  • Try the samples runs it on sixteen texts, and lists what it made of each one.

Reload

Reload, on a plugin's page, loads it again from where it came from: a link is fetched again, and a file loaded on a Mac is read again from where it is. A pasted plugin, or a file picked on Android, has no Reload: paste it or pick it again, and the new copy takes the old one's place.

  • A copy with problems doesn't take the place of one that works: the last good copy keeps running, and the new copy's problems are listed.
  • A copy whose id has changed is refused: "The copy's id is now billz: load it as a new plugin."
  • A copy that can do more than you agreed to, a new permission, a new link or a new tab, is switched off until you agree again: switching it on shows the sheet again, with what it can do now.

Problems and errors

A plugin's page lists Problems, its newest copy's, each with its code, where it is in the file (rules.tags[0].any[2], or nothing for the whole file) and what's wrong in words, and Lately: what it ran into while running, newest first, such as a button the app refused. A load that isn't JSON, or has no id the app can use, adds no row at all: a sheet lists its problems, with Copy the problems.

Errors stop a plugin loading and being submitted, and its row counts them as problems. Warnings don't, and its row counts them apart (1 warning), but a reviewer sees them too:

From your computer, through the API

With the phone plugged in by USB and Settings › API › Serve the API on (Developer API), a script can load, try and remove plugins in development:

adb forward tcp:8765 tcp:8765

# Load it: the file's JSON as "pack" (or its words as a string, "text")
printf '{"pack": %s}' "$(cat bills.ghostplugin)" | curl -s http://localhost:8765/api/plugins.devInstall \
  -H 'Authorization: Bearer <token>' --data-binary @-

# Only check it, loading nothing
printf '{"dryRun": true, "pack": %s}' "$(cat bills.ghostplugin)" | curl -s http://localhost:8765/api/plugins.devInstall \
  -H 'Authorization: Bearer <token>' --data-binary @-

# What the phone's plugins that are on make of a text
curl -s http://localhost:8765/api/filters.classify -H 'Authorization: Bearer <token>' \
  -d '{"text": "Your bill is ready. Amount due: $45.20 by 3 Dec."}'

# Remove it
curl -s http://localhost:8765/api/plugins.devRemove -H 'Authorization: Bearer <token>' -d '{"id": "bills"}'
  • plugins.devInstall answers {"ok": true, "id": "bills", "plugin": "xbills", "on": false, "issues": []} inside the API's own result. A plugin with problems isn't an error: it answers "ok": false with every one in issues.
  • It loads switched off. "on": true switches it on only where you've agreed on the phone to everything it can do already; otherwise it answers "on": false and "needs": "consent on the phone". The phone says whenever a plugin was loaded from the API, so nobody with your token can load one unseen.
  • filters.classify asks only the plugins that are on. A plugin first loaded from the API is off until you've agreed on the phone to what it can do: switch it on once in Settings › Developer › Plugins in development. After that a load with "on": true switches it on too. Until then filters.classify shows only the built-in plugins' tags.
  • Once it's on, filters.classify gives the tags under their names in the app (xbills.bill: $45.20) and the section it would go to: xbills0bills, or another plugin's where a built-in plugin takes it first (with Kinds of text on, the example bill goes to its reminders).
  • plugins.list says each plugin's source (builtIn, reviewed or dev) and version.
  • With Developer mode off they answer "Turn on developer mode first: tap Settings › About › Version twelve times."

Which texts a plugin sees

A plugin sees only texts from one person not in your contacts, in words known to be theirs, not sent with Uplink's encryption, and never chats on other networks, circles or spaces (all of it). When you test on real texts:

  • A text from someone in your contacts does nothing, nor does a group, or your own message.
  • A conversation you started that's had no answer yet isn't seen until something comes back.
  • A text with a sign-in code in it is tagged, and nothing more.
  • Try it (on or off) and filters.classify (once it's on) always count as a stranger's text, so they're the quickest way to test.

Testing the next version of a listed plugin

Your copy in development and the Marketplace's copy of the same plugin can't both be on one device. To try your next version:

  1. Remove the Marketplace's copy

    On its page in the Marketplace, tap Remove. Your choices for it are kept.

  2. Load yours

    Load your new version in Settings › Developer › Plugins in development, and try it as above.

  3. Then put things back

    When you're done, remove your copy there, and add the Marketplace's again from its page. Once your new version is approved, it's an update like anyone else's.
