APIs

App API

Control the app from a script or another program: every method, what it takes and what it answers.

Uplink has an API: every part of the app, from your conversations to its screens, as methods you can call from a script or another program. It's off until you turn it on, and only someone with your token or connection string can use it.

Turn it on

  1. Developer mode

    On your phone, tap Settings › About › Version twelve times. Taps more than two seconds apart start the count again, and from the eighth tap a note counts down. Then Settings › Developer and Settings › API appear.

  2. Choose how to reach it

    • Serve the API: over HTTP on the phone. From a computer by USB: adb forward tcp:8765 tcp:8765, then call http://localhost:8765. Allow from Wi-Fi serves it on your network too.
    • Through the relay: from anywhere. The connection string (ghostapi1:…) holds the key every call is sealed with; the relay passes calls along without being able to read them. Keep it as you would a password.

Call a method

Over HTTP, POST /api/<method> with the parameters as a JSON body and your token:

curl -s http://localhost:8765/api/conversations.list \
  -H 'Authorization: Bearer <token>' \
  -d '{"limit": 5}'

Or with the command-line client in the app's repository (tool/ghost-api.mjs):

node tool/ghost-api.mjs --token <token> app.info
node tool/ghost-api.mjs --remote ghostapi1:<secret> networks.chats '{"network": "telegram"}'

With no method it lists them all; --doc <method> shows one's documentation.

Requests and answers

RequestWhat it does
GET /apiEverything the API says of itself: every method, as JSON (api.describe).
GET /api/<method>One method's documentation.
POST /api/<method>Calls it. The body is its parameters as a JSON object, or empty.
POST /apiThe same as one object: {"method": "…", "params": {…}, "id": …}. The id comes back with the answer.

Every request but GET / needs Authorization: Bearer <token>. Answers are JSON:

{"ok": true, "result": …}
{"ok": false, "error": {"code": "bad_params", "message": "\"thread\" is needed: …"}}
CodeStatusMeaning
unauthorized401The token is missing or wrong.
not_found404No such method, or what it named isn't there.
bad_params400A parameter is missing or of the wrong type, or the body isn't a JSON object. Also 405 for anything but GET and POST.
failed500The method ran and what it asked failed. The message says why.

Parameter types are string, int, bool, list and object, and each call is checked against them before it runs.

Through the relay

The connection string is ghostapi1: and 64 hex digits: a secret of 32 bytes. Both ends make three things from it with HKDF-SHA256 (salt ghost-api v1): the pairing channel they meet on (info relay channel, its first 16 bytes), that channel's token (relay token), and an AES-256-GCM key (seal key). The app holds the channel as its phone end; a client joins as the other (Pairing channels).

A request is one binary frame: a 12-byte nonce, then {"method", "params", "id"} sealed with the key (additional data ghost-api-v1, GCM's tag at the end). The answer comes back the same way. The relay passes the frames and can't open them. The app must be running to answer. tool/ghost-api.mjs is a client of about 150 lines to read or copy from.

The methods

Settings › API › Methods lists the same, with a place to try each. Those marked changes things send, delete or change something, and ask before running there. The methods for plugins in development need developer mode and aren't in App Store builds.

Every method, its parameters, what it answers and an example: this documentation as JSON.

Answers {"api", "version", "methods": [...]}

curl -s http://localhost:8765/api/api.describe -H 'Authorization: Bearer <token>'

Answers at once: whether the API is there and which version it speaks.
